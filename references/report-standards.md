# 报告写作规范

> 供「明察Pro」阶段 7-8 调用。HTML 报告的技术规格见 SKILL.md 阶段 8 路线 B，本文管内容结构与写作纪律。

## 一、逻辑链条

```
背景 → 现状 → 驱动因素 → 瓶颈/风险 → 未来演化 → 结论
```

每部分都要有"分析"，不能只罗列信息；体现研究员视角。

## 二、Markdown 报告结构（默认交付模板）

```
# [主题] 深度研究报告

## 摘要（300-500字，概述核心发现）
## 一、研究背景
   1.1 研究主题界定 / 1.2 研究意义 / 1.3 研究方法与数据基期
## 二、核心问题与分析框架
   2.1 核心问题 / 2.2 分析框架 / 2.3 关键假设
## 三、现状与关键事实
   3.1 发展历程 / 3.2 当前状态 / 3.3 关键数据
## 四、深层驱动逻辑
   4.1 技术驱动 / 4.2 市场驱动 / 4.3 政策驱动 / 4.4 资本驱动
## 五、主要矛盾与争议点
   5.1 核心矛盾 / 5.2 观点分歧 / 5.3 矛盾信息与置信度清单
## 六、未来趋势与情景推演
   6.1 趋势判断 / 6.2 情景分析 / 6.3 概率评估
## 七、风险因素与反证条件
   7.1 主要风险 / 7.2 反证条件（什么信号出现推翻核心判断）/ 7.3 风险应对
## 八、结论与建议
   8.1 核心结论 / 8.2 行动建议 / 8.3 跟踪指标
## 附录：数据来源清单（S/A/B 分级）、参考文献
```

核心发现 3-5 条，每条配数据支撑；详细分析按维度分节（技术/商业/政策/用户等）。

## 三、区分层级（每条结论必须归层）

| 层级 | 说明 | 示例 | 置信度 |
|---|---|---|---|
| 事实 | 客观存在、多源验证 | "2024年市场规模为X亿"（来源n） | 高 |
| 推论 | 基于事实的推理 | "基于增长率，预计……"（推测） | 中 |
| 判断 | 主观评估 | "我们认为……" | 低 |

## 四、标准结论格式

```markdown
## 结论与建议

### 核心结论
1. **[结论1]**（置信度：高/中/低）
   - 依据：...
   - 含义：...
   - 验证/证伪信号：...

### 最值得跟踪的变化变量
- 变量1 / 变量2

### 最容易出现误判的点
- 误判点1 / 误判点2
```

置信度：高（>90%，数据充分逻辑清晰）/ 中（70-90%，有依据但有不确定性）/ 低（<70%，信息有限或争议大）。

## 五、写作风格与措辞纪律

- 像专业券商/咨询/产业研究报告：数据驱动、逻辑严密、避免主观臆断
- 有依据的结论明确引用来源；推测性判断标注"推测"；证据不足明写"证据不足"

```
✓ "根据XX数据，..." / "综合多方信息，..." / "据XX估算，..." / "证据不足，但倾向于认为..."
✗ "肯定是..." / "毫无疑问..." / "绝对..."
```

- 无来源数字不入正文；查不到就写"公开信息有限"，绝不补造
- 正文标注数据基期与时效；趋势预测以当年为基准

## 六、报告类型侧重

| 类型 | 必写模块 |
|---|---|
| 行业报告 | 产业链分析、市场规模、竞争格局、发展趋势 |
| 公司分析 | 商业模式、竞争优势、财务状况、投资/合作价值 |
| 政策解读 | 政策背景、核心内容、影响分析、应对策略 |
| 技术报告 | 技术原理、发展现状、应用前景、突破方向 |
| 学术综述 | 发展脉络、主要方法对比、关键发现与争议、未来方向 |
| 舆情分析 | 热点话题、情感分布、传播路径、风险预警 |

## 七、学术场景附件格式

**论文卡片**：标题（链接）/ 作者 / 机构 / 年份 / 期刊会议 / 引用数 / 摘要 / 关键贡献 / 方法 / 代码链接。

**综述报告结构**：概述（背景/搜索策略/时间范围）→ 发展脉络 → 主要方法（类别+对比）→ 关键发现（共识+争议）→ 未来方向 → 参考文献。
