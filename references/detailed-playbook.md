# 明察Pro 深度执行手册（Detailed Playbook）

> 本文件解决一个核心问题：**「深度研究」到底深在哪、每一步具体做什么、写到多细算合格。**
> methodology.md 给的是「框架与指标」，本手册给的是「逐阶段的操作细则 + 报告写作密度要求」。
> 执行时，阶段 1-6 对照本手册逐条落地；阶段 7-8 对照「写作密度」部分逐段检查。

---

## 〇、总原则：什么叫「详细」

「详细」不是「字数多」，而是**每个结论都能回答「为什么、怎么来的、有多少把握」**。四条硬标准：

1. **可追溯**：正文每个数字/判断都能向上追到某个来源（S/A/B 级）与某次搜索。
2. **有过程**：不只是给结论，要给「我们查了什么、排除了什么、为什么信 A 不信 B」。
3. **有颗粒度**：不写「市场很大」，写「2025 年规模 X 亿，其中 Y 细分占 Z%，增速 W%，驱动因素是……（来源）」。
4. **有边界**：明确写出「这个数字查不到」「这个判断只有单一来源」「这里可能存在口径差异」。

**反面教材对照**（详细 vs 不详细）：

| 维度 | ✗ 不详细（要避免） | ✓ 详细（要达到） |
|---|---|---|
| 市场规模 | "市场规模很大" | "2025 年全球智能手机出货 12.2 亿台，小米 1.65 亿台占 13.5%（Omdia 口径），同比 +X%" |
| 竞争格局 | "竞争激烈" | "前五厂商为 A/B/C/D/E，市占分别为 19%/18%/14%/9%/9%，小米列第三且在中低价位带领先（来源）" |
| 风险 | "存在风险" | "风险一是存储芯片涨价：消费级 DRAM/NAND 价格半年涨 60%+，内存占中低端机型物料成本升至 40%，直接压毛利（来源）" |
| 结论 | "看好长期发展" | "估值修复取决于手机毛利率重回 10%+、汽车月交付站上 5 万辆、AI 产生可量化回报三个可验证信号（置信度：中）" |

## 一、阶段 1：问题解构 —— 拆到什么颗粒度

**目标产物**：一份「子问题清单」，每项都是**一个能直接搜索的具体问题**，不是宽泛主题。

**拆解规则**（4 条，缺一不可）：
1. **数量**：10-20 个子问题（深度档可到 30）。
2. **维度交叉**：技术 × 商业 × 政策 × 用户 × 财务 × 风险，六维至少覆盖四维；空间上国内/国际都要有。
3. **时间分层**：历史（怎么来的）/ 现状（现在什么样）/ 趋势（往哪去）各至少 1 项。
4. **颗粒度检验**：每个子问题都必须能用一个 `主语 + 动词 + 具体对象` 的搜索句表达。

**模板（企业调研场景直接套用）**：
```
实体层：这个主体的精确注册名、信用代码、曾用名、英文名、品牌名分别是什么？
工商层：注册资本（认缴/实缴）、成立时间、法代、状态、经营范围、登记机关？
股权层：股东穿透到实控人是谁？股权结构图？近年股权变更？对赌/质押？
管理层：核心高管名单、背景、任职时间、近期人事变动？
业务层：主营产品线、收入结构、各业务占比、核心客户/供应商？
财务层：近 3-5 年营收/利润/毛利率/净利率、现金流、负债、资产负债率？
竞争层：所处赛道的市场规模、增速、CR5/CR10、主要竞对及各自份额？
技术层：核心专利/技术壁垒、研发投入、技术路线、卡脖子环节？
用户层：用户规模、画像、口碑、满意度、复购/留存、投诉集中点？
政策层：所处行业的监管政策、牌照、合规风险、政策利好/利空？
风险层：司法案件、被执行、经营异常、股权冻结、重大负面舆情？
动态层：近 1-2 年大事件、融资/并购、招聘信号、展会/发布会动作？
```
> 每一步搜索前，把上面 12 层**逐层问一遍**，缺哪层就补哪层的子问题。这是「详细」的第一道保险。

## 二、阶段 2：搜索策略 —— 关键词怎么造

**目标产物**：每个子问题的「关键词矩阵」，至少 3 组变体。

**关键词矩阵公式**（每个子问题配满）：
```
主词        同义词/别名        上位词        相关词        排除词
小米集团    Xiaomi Corp        消费电子      人车家         -小米手机壳
            1810.HK            智能手机      生态链        -招聘广告
```
**造词清单**（每项子问题都要过一遍）：
1. 中文名 + 英文名 + 股票代码/统一信用代码（如 `小米集团`、`Xiaomi Corporation`、`1810`、`01810.HK`）
2. 别名/曾用名/简称（如 `小米`、`小米科技`、`Mi`）
3. 上位词（如 从「小米汽车」上溯到「新能源车 / 智能电动车」）
4. 下位词（如 从「小米汽车」下钻到「SU7 / YU7 / 御风 SkyNomad」）
5. 时间限定词（`2025 年报`、`2026 最新`、`Q2 财报`）
6. 信源限定词（`港交所`、`天眼查`、`财报`、`公告`）
7. 高级语法：`"精确短语"`、`site:mi.com`、`filetype:pdf`、`-排除词`

**搜索词质量自检**：这组词能命中 S/A 级信源吗？会不会漏掉英文一手资料？有没有把「官方披露」和「媒体转述」分开搜？

## 三、阶段 3：原子搜索 —— 一次搜一个，记全

**执行规则**：
1. **一次一个原子问题**，单条消息内可并行发起多个 WebSearch/WebFetch，但每个调用只服务一个子问题。
2. **双语**：每个关键子问题至少中英各搜一次（一手财报、外媒、英文数据常只在英文源）。
3. **边搜边记**：每轮搜索后，立即把命中的「关键数字 + 来源 + 信源级别 + 时间」记进脑内证据表，不要攒到最后。

**搜索后必须回答的 5 个问题**（每轮都要过）：
```
Q1 这条信息说了什么核心事实/数据？
Q2 它来自哪一级信源（S/A/B/C）？发布/更新于何时？
Q3 它与我已有的信息一致吗？不一致的点是什么？
Q4 它填补了哪个子问题的空白？还是引出了新问题？
Q5 有没有值得继续深挖的线索（引用、作者、项目、数据源头）？
```

**搜索轮次分配**（深度档 20-30 轮时）：
```
全景扫描（5-8 轮）：广度铺开，建立领域地图
节点筛选（3-5 轮）：按权威性+相关性筛出高价值源
深度挖掘（8-12 轮）：引用追踪/作者追踪/项目追踪，聚焦 S/A 级
交叉验证（3-5 轮）：核心事实三源互证
迭代补充（2-3 轮）：补空白、追最新动态
```

## 四、阶段 4-5：信源分级 + 交叉验证 —— 怎么「验」

**分级落地表**（不只是背定义，要会归位）：
```
S 级：官方公告、经审计年报/中报、监管披露（港交所/证监会）、判决书、顶会顶刊论文
A 级：天眼查/企查查/爱企查工商数据、Gartner/IDC/Omdia 报告、财新/证券时报等深度报道
B 级：企业官网自述、招聘页、技术博客、雪球/知乎深度分析、外媒一般报道
C 级：预印本、社交媒体、匿名来源、自媒体转述
```

**交叉验证三问**（核心事实逐条过）：
```
1. 这个数字有 ≥3 个独立来源吗？（同源转载不算独立）
2. 有没有追溯到原始出处？（媒体转述的要追到财报原文/官方公告）
3. 三个来源口径一致吗？（不一致就进矛盾清单，不许悄悄取一个）
```

**矛盾处理五步**（标志性动作，务必执行）：
```
记录差异 → 分析原因（口径/时点/立场/单位）→ 给出采用值 → 标注置信度 → 写入矛盾清单
```

## 五、阶段 6：迭代反思 —— 什么时候算「挖够了」

**饱和判定清单**（逐条打勾）：
- [ ] 12 层子问题（或本场景等价维度）是否全部覆盖？
- [ ] 每个核心结论是否都有 S/A 级信源支撑？
- [ ] 关键数字是否都完成了三源交叉验证？
- [ ] 是否同时呈现了支持方 / 反对方 / 中立方观点？
- [ ] 矛盾是否都已记录而非抹平？
- [ ] 最新动态是否已追到「最近一个月内」？
- [ ] 是否还能搜出「新的、不同的」信息？（搜不出了 = 饱和）

**终止条件**：信息饱和度 >90% 或连续 2 轮无新发现，即可进入阶段 7；默认最多 3 轮反思。

## 六、阶段 7-8：结论与报告 —— 写到多细算合格

### 6.1 结论分层的落地标准

| 层级 | 判定 | 写法要求 |
|---|---|---|
| 事实 | ≥3 独立来源 + S/A 级 | 直接陈述，括号标来源：「2025 年营收 4573 亿元（2025 年报）」 |
| 推论 | 有事实基础但需推理 | 必须写推理链：「因 X、Y、Z，故推断……（推测）」 |
| 判断 | 观点/预测 | 必须配「验证/证伪信号」：「若 A 出现则成立，若 B 出现则推翻」 |

### 6.2 报告的「详细度」硬要求（每条都要达标）

1. **每个数字三件套**：数值 + 单位 + 来源/时间。禁止裸数字。
2. **每个判断两件套**：理由 + 置信度徽章（高/中/低）。
3. **每个矛盾一条记录**：进「矛盾信息与置信度清单」，至少 3 行。
4. **每段有分析不是罗列**：写完事实，紧跟一句「这意味着……」。
5. **每个趋势给基期**：「以 2025 年为基准，预计 2026 年……」。

### 6.3 逐段写作密度对照（Markdown 报告）

```
摘要：300-500 字，必须含「对象是谁 + 3 条核心发现（每条带 1 个数字）+ 1 条风险」
背景：研究范围 + 数据基期 + 为什么研究（不空谈意义）
现状：关键事实分维度写，每个维度配 1-3 个有来源的数字
驱动逻辑：技术/市场/政策/资本，每条讲清「因果链条」而非贴标签
矛盾争议：核心矛盾 + 多方观点 + 矛盾清单表格
趋势情景：至少给「基准/乐观/悲观」三情景，各配概率与触发条件
风险反证：主要风险 + 明确的证伪信号（什么情况推翻主线）
结论建议：核心结论（带置信度）+ 行动建议 + 跟踪指标清单
来源附录：S/A/B 分级 + 可点击链接
```

### 6.4 深度档位对详细度的映射（按用户意图分流）

> **分级触发**：普通「研究/查一下」走标准档；用户带「深度/深入/彻底/全面/挖透/尽调」字眼或语气明显要更透时，自动升深度档；只有用户明确说「快速/简版/概览」才降基础档。

| 档位 | 触发条件 | 搜索轮次 | 报告详细度 |
|---|---|---|---|
| 基础 | 用户明确要「快速/简版/概览」 | 10-15 轮 | 覆盖核心事实，每维度 1 个数据点 |
| 标准 | 默认（「研究/查一下/了解」） | 15-20 轮 | 每维度 2-3 个数据点 + 矛盾清单 + 三情景 |
| 深度 | 「深度/深入/彻底/全面/挖透/尽调」 | 20-30 轮 | 全部数据点 + 完整推理链 + 交叉验证记录 + 引用追踪 |

> 详细是明察Pro 的本分；深度档由用户语气触发，不是「不满意时再补救」。

### 6.5 深度执行清单（深度档逐项做满，非可选加成）

- [ ] 增加信源类型：补学术库（arXiv/Google Scholar）+ 英文一手财报原文
- [ ] 增加时间颗粒度：补「分季度」而非「分年度」数据
- [ ] 增加空间颗粒度：全球拆到区域（东南亚/欧洲/拉美/中东非洲分别写）
- [ ] 增加链条颗粒度：把「驱动因素」拆到「具体机制 + 数据佐证」
- [ ] 增加对立视角：每章补一段「反方怎么看 + 反方证据」
- [ ] 增加可验证性：每个核心判断配「验证信号 + 证伪信号 + 跟踪频率」
- [ ] 增加交叉验证记录：把「三源互证过程」写进附录
- [ ] 增加竞对对照：关键指标与主要竞对并列对比表

## 七、逐阶段「合格」验收单（每阶段做完对照）

| 阶段 | 合格标志（缺一不可） |
|---|---|
| 1 解构 | 产出 10-20 个「能直接搜索」的子问题，覆盖 ≥4 维度 |
| 2 策略 | 每个子问题有 ≥3 组关键词变体，含双语 |
| 3 搜索 | 每轮回答 Q1-Q5，双语覆盖，有证据表 |
| 4 分级 | 每个来源归到 S/A/B/C，S/A 占比 ≥40% |
| 5 验证 | 核心事实三源互证，矛盾进清单 |
| 6 反思 | 饱和度 >90% 或连续无新发现，才进入 7 |
| 7 结论 | 每条带层级 + 置信度 + 来源 |
| 8 报告 | 数字三件套、判断两件套、矛盾 ≥3 行、段段有分析 |
