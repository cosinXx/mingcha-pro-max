# 明察Pro 搜索战术手册（Search Playbook）

> 三本手册分工：`methodology.md` 管**方法论框架**（8 阶段、稀疏注意力、硬指标）；`detailed-playbook.md` 管**写作与验收颗粒度**；**本手册管「检索怎么执行」**——研究方案怎么写、搜索怎么分工、证据怎么记、坑怎么绕。
> 执行顺序建议：先读本手册定方案 → 按本手册执行检索 → 用 detailed-playbook 的验收单核对 → 用 report-standards 写作。

---

## 一、阶段 0：先出「研究方案」再开搜（本次新增的硬动作）

**核心原则：搜索前先有方案。没有方案的搜索 = 乱枪打鸟，轮次花光还漏维度。**

### 触发规则
- **深度档**：必须先产出「研究方案卡」，并用 1 屏篇幅向用户简述（口径、边界、子问题、档位），确认后开搜；用户明确说"直接开始/不用问"时跳过确认但仍要内部拟定。
- **标准档**：内部拟定方案卡（不必展示），但子问题清单和关键词矩阵必须有。
- **基础档**：至少列出 5-8 个子问题。

### 研究方案卡模板（8 项，逐项填满）

```
【研究方案】<对象/主题>

1. 研究目标：一句话说清「要回答什么」（例：判断 XX 公司当前经营状况与主要风险）
2. 研究边界：对象界定 / 时间范围 / 明确不含什么（防范围蔓延）
3. 子问题清单：10-20 个可搜索的具体问题，按维度分组
4. 维度矩阵：技术 · 商业 · 政策 · 用户 · 财务 · 风险  ×  国内/国际  ×  历史/现状/趋势
5. 关键词矩阵：每个子问题 ≥3 组变体，中英双语（造词法见 detailed-playbook 第二节）
6. 信源计划：优先攻哪几类 S/A 级源？（官方财报/监管披露/权威机构/工商平台）
7. 轮次预算：全景 5-8 / 挖掘 8-12 / 交叉验证 3-5 / 补充 2-3
8. 交付与档位：Markdown 或 HTML；标准档或深度档
```

**方案卡自检**：每个子问题能不能变成一句搜索？六大维度有没有缺？有没有把"官方一手数据"列为必攻目标？

## 二、搜索工具分工（关键认知：搜 ≠ 证）

| 工具 | 定位 | 特点 | 用途 |
|---|---|---|---|
| WebSearch | 铺面、发现 | 快、广、浅 | 摸信息地形、找高价值链接、建立领域地图 |
| WebFetch | 取证、核验 | 慢、准、深 | 打开原文、抓具体数字与原文表述、确认口径 |

### 三条铁律
1. **没打开过原文的链接，不得作为 S/A 级引用。**搜索摘要里的数字必须回原文核验后才能进正文。
2. **摘要 ≠ 原文。**媒体转述的"据财报显示"必须追到财报原文；追不到就在台账里降级标注。
3. **一轮的节奏**：搜索铺面 → 挑 3-5 个高价值链接 → 批量 WebFetch 取证 → 更新证据台账 → 进入下一轮。

### 并行规则
单条消息内可并行多个 WebSearch/WebFetch，但**每个调用只服务一个原子子问题**；同一轮里可同时铺中英文两条线。

## 三、跨领域关键词实例（照着改）

> 公式：主词 + 别名/代码 + 时间/信源限定 + 上位/下位词 + 反方词。以下为各场景可直接复用的查询串样例。

**企业尽调**
```
「XX 集团 注册资本 法定代表人 统一社会信用代码」（工商底档，主攻天眼查/企查查）
「XX 股权结构 实际控制人 持股比例 年报」（股权穿透，主攻年报/公告）
「XX 2025 年报 营收 净利润」（财务，主攻港交所/巨潮/交易所披露）
「XX 诉讼 被执行 经营异常 行政处罚」（风险面）
「XX 参保人数 招聘 规模」（规模交叉验证）
```

**行业研究**
```
「XX 行业 市场规模 2026」（规模）
「XX 行业 竞争格局 CR5 市占率」（格局）
「XX 行业 政策 监管 新规」（政策）
「XX industry market size 2026 report」（英文一手机构报告）
「XX 行业 产业链 上游 下游」（链条）
```

**技术调研**
```
「XX 技术 原理 实现 架构」
「XX vs YY 技术路线 对比 优劣」
「XX arxiv paper 2025」/「XX 综述 survey」
「XX 开源项目 github star 活跃度」
「XX 技术 瓶颈 局限 失败」（反方）
```

**学术综述**
```
「XX 系统综述 systematic review」
「XX 研究进展 2024 2025 综述」
「XX 领域 关键论文 高被引」（Google Scholar/Semantic Scholar）
「XX 争议 局限 limitations」
```

**舆情 / 事件**
```
「XX 事件 时间线 起因 经过」
「XX 官方回应 声明」
「XX 舆情 争议 质疑」（反方）
「XX 最新进展」（时间过滤：24h / 一周 / 一月）
「XX 事件 BBC Reuters」（国际视角）
```

**人物 / 机构背景**
```
「XX 履历 任职 教育背景 官方简历」
「XX 关联企业 对外投资」
「XX 争议 负面 处罚」（风险面）
「XX interview profile Reuters Bloomberg」（英文侧写）
```

**政策解读**
```
「XX 政策 原文 全文」（主攻政府官网/部委公告，S 级）
「XX 政策 解读 影响 专家」
「XX 政策 实施时间 过渡期 细则」
「XX 政策 争议 反对」（多方解读）
```

## 四、证据台账（边搜边记，可追溯性的骨架）

**为什么要记**：20-30 轮之后没人能凭记忆对齐"哪个数字来自哪个源"。台账就是报告的原材料仓，报告里每个数字都要能在台账里找到对应行。

### 台账字段（每轮搜索后立即追加）
```
| # | 子问题 | 关键信息/数字 | 来源（名称·级别） | 发布时间 | 是否已核原文 | 冲突情况 |
|---|--------|--------------|------------------|---------|------------|---------|
| 1 | 2025营收 | 4573 亿元 | 2025年报（S） | 2026-03-24 | ✅ 已核 | — |
| 2 | 市值 | 6493 亿港元 | TraderUnion（B） | 2026-10-01 | ❌ 未核 | 与另一源 5806 亿冲突→进矛盾清单 |
```

### 记录规则
- **一条事实一行**，不合并；
- "是否已核原文"栏是**诚实度开关**——没核的不能当 S/A 用；
- 有冲突的立即在最后一栏标记，不必当场解决，但**绝不能丢**；
- 台账不必给用户看，但**报告写完后要能逐条回溯**。

## 五、反方搜索（Red Team 前置到检索层）

**为什么必须前置**：只搜利好会得到一间回音壁，成稿时再补 Red Team 就只是打补丁。**主动搜反证，是深度研究区别于资料收集的分水岭。**

### 反方搜索四类查询
```
① 质疑类：XX 质疑 / 争议 / 翻车 / 失败 / 风险 / 造假 / 看空 / 泡沫
② 失败案例：XX 失败教训 / 前车之鉴 / 同赛道 倒闭 / 暴雷
③ 反方观点：XX 不看好 / 高估 / 天花板 / 现金流压力
④ 监管诉讼：XX 处罚 / 诉讼 / 监管调查 / 召回 / 合规
```

### 执行标准
- **至少 20% 的检索轮次用于反方搜索**；
- 反方证据无论成立与否，都要记进台账，并判断"是否构成实质性反证"；
- 找不到反证也要在报告中写明：**"已做反方检索，未见有力反证"**（这句话本身是结论强度的一部分）；
- **结论强度取决于反证检验的强度，而非支持论据的数量。**

## 六、搜索失败模式与破解（搜不到怎么办）

| 症状 | 可能原因 | 破解动作 |
|---|---|---|
| 搜不到 / 结果很少 | 关键词太窄、术语不对 | 换上/上位词、换英文、去掉限定词、放宽时间范围 |
| 全是软文 / 内容农场 | 商业词吸流量文 | 加 `site:` 限定权威源、加「年报/公告/财报/白皮书」、改用英文搜 |
| 只有中文能搜到 | 对象是本土主体 | 补英文名/股票代码/拼音搜海外报道；接受「仅中文信源」并标注 |
| 全文打不开（付费墙） | 版权限制 | 用官方摘要/财报原文/监管披露替代；**绝不绕过付费墙**；标注「原文受限，依据公开摘要」 |
| 同名实体混淆 | 名称歧义 | 先做实体核验（信用代码/股票代码锚定），报告中明确所采用主体 |
| 数据都很旧 | 缺最新披露 | 搜「最新 / 2026 / 半年报」；确认是否尚未到披露期；未披露就如实写 |
| 数字前后打架 | 口径/时点不同 | 进矛盾清单，按「口径→时点→独立性」三步归因，给出采用值 |
| 只能找到企业自述 | 缺第三方数据 | 降级为 B 级并显名归因；同时继续找第三方交叉源 |

**兜底原则**：查不到就写「公开信息有限」，**绝不补造、绝不用隐约约的表述蒙混**。

## 七、数字校验协议（防低级错误）

进正文前，每个数字过五道闸：

```
① 单位：亿 / 万亿 / 万 ——换算后回读一遍（4573 亿元 = 4,573 亿，别再写成 457.3 亿）
② 币种：人民币 / 港元 / 美元 —— 必须标清（港股市值用港元、港股公司营收常用人民币，混用即错）
③ 口径：集团 vs 单体 · 认缴 vs 实缴 · 出货量 vs 销量 · GMV vs 营收 · 含税 vs 不含税
④ 量级 sanity check：净利 > 营收、毛利率 > 100%、市占率合计 > 100% = 必然有错，回头查
⑤ 时间对齐：同比 vs 环比基期一致？财年 vs 自然年一致？
```

**信源独立性判定**（决定"A 级"能不能算作独立一票）：
```
✗ 不算独立：同一篇通稿被 5 家媒体转载 / 都引用同一个调研机构且无新数据
✓ 算独立：不同机构、不同原始数据源、不同采集方法
核心事实要求「3 个独立来源」，指的是 3 条独立证据链，不是 3 个网页。
```

## 八、时效锁定与数据基期

1. **开搜前先问**：这个话题的「最新一次官方披露」是什么时候？（财报季节奏：A 股/港股 3-4 月年报、8-9 月中报、10-11 月三季报）
2. **正文必须标数据基期**：如「截至 2026Q2 财报」「截至 2026-10-01 行情」。
3. **趋势预测以当年为基准**，并写明假设。
4. **最新披露缺失时**：明写「截至检索日，最新官方披露为 X 期数据，Y 期尚未发布」。

## 九、检索阶段验收单（每轮 / 收尾时对照）

| 检查项 | 合格标志 |
|---|---|
| 研究方案 | 深度档有方案卡；子问题 10-20 个，覆盖 ≥4 维度 |
| 关键词 | 每个子问题 ≥3 组变体，含中英双语 |
| 工具分工 | 关键数字有 WebFetch 原文核验记录 |
| 证据台账 | 每条核心事实有台账行，「已核原文」栏明确 |
| 反方搜索 | ≥20% 轮次用于反方；有反证结论或"未见有力反证"声明 |
| 失败模式 | 无「搜不到就硬写」的内容；受限来源已标注 |
| 数字校验 | 单位/币种/口径/量级/时间五项过关 |
| 时效 | 数据基期已标注；最新披露状态已说明 |
| 信源独立性 | 核心事实 ≥3 条独立证据链（非转载） |
| 饱和度 | 12 层/等价维度全覆盖，或多轮无新发现 |
