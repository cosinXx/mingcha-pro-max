# 专家手册（Expert Playbooks）

E01–E10 通用专家角色。Phase 0 按主题相关性挑选 4–6 位；每位专家认领一个子命题，输出"判断 + 证据 + 量化 + 缺口 + 对主线印证/挑战"的标准分片。

| ID | 专家 | 职责与检索要点 | 典型信源 |
|----|------|----------------|----------|
| E01 | 主题解构专家 | 拆问题树、定边界、识别用户焦点；不检索，负责结构 | — |
| E02 | 领域全景专家 | 领域定义、边界、发展阶段、规模与增速、历史脉络 | 官方统计、行业白皮书、学术综述 |
| E03 | 技术与产品专家 | 技术路线、核心机制、产品形态、演进趋势、评测基准 | 论文、技术博客、官方文档、Github |
| E04 | 市场与竞争专家 | 市场格局、竞争格局、份额、定价、渠道、壁垒 | 券商研报、财报、咨询机构、行业数据 |
| E05 | 商业与财务专家 | 商业模式、盈利质量、单位经济、现金流、估值逻辑 | 财报、招股书、财务数据库、分析师报告 |
| E06 | 政策与监管专家 | 政策法规、监管动态、合规要求、产业政策 | 政府官网、法规数据库、权威媒体 |
| E07 | 用户与需求专家 | 用户画像、需求动机、体验痛点、采纳障碍、社会影响 | 用户社区、问卷调研、应用商店评价 |
| E08 | 事实核查专家 | 对 E02–E07 的关键事实做溯源、交叉验证、归级 | 全部一二级信源 |
| E09 | 反方 Red Team 专家 | 攻击主线判断：找反证、极端情景、敏感性压力测试；输出"什么信号出现就推翻主线" | 批判性文章、失败案例、监管处罚记录 |
| E10 | 综合编辑专家 | 落判断主线底稿、篇章组织、数据一致性核对、定稿 | — |

## 选择规则

- **必选**：E02（全景）+ E08（核查）+ E09（反方）——保证深度、真实性与可证伪。
- **按主题选 1–3 个**：技术主题加 E03；商业/投资主题加 E04、E05；政经主题加 E06；社会/消费主题加 E07。
- 专业领域（医疗、法律、金融建模等）存在更专业的 Skill 时，优先调用对应 Skill 的检索通道与规范，专家职责不变。

## 输出纪律

- 每条判断必须挂证据；每条证据必须带来源 URL、可信度级别（一/二/三）、数据基期、单位与口径。
- 数字照抄原始口径，不换算不拔高；易被拔高的数字（份额、渗透率、增速）必须注明"谁说的、什么口径"。
- 查不到就写缺口，不编造。
