# 深度研究方法论

> 本方法论是「明察Pro」自有体系，供阶段 1-6 调用。
> **配套**：检索操作细则见 `search-playbook.md`（研究方案/工具分工/证据台账/反方搜索/数字校验）；写作颗粒度见 `detailed-playbook.md`。

## 一、8 阶段深度研究流水线（主流程）

```
阶段1 问题解构 → 阶段2 搜索策略 → 阶段3 原子搜索 → 阶段4 信源分级
                                                      ↓
阶段8 报告生成 ← 阶段7 结论输出 ← 阶段6 迭代反思 ← 阶段5 交叉验证
```

**阶段1 问题解构**：把复杂问题拆成 10-20 个可搜索的原子子问题；确定时间范围（历史/现状/趋势）和维度（技术/商业/政策/用户），兼顾空间（国内/国际/区域）与层次（宏观/中观/微观）。

**阶段2 搜索策略**：构建四个矩阵——
- 关键词矩阵：主词 + 同义词 + 上位词 + 下位词 + 相关词 + 排除词
- 信源矩阵：学术 / 新闻 / 社区 / 官方 / 行业报告
- 语言矩阵：中文 + 英文
- 时间矩阵：最新 / 近期 / 历史

策略类型：广度优先（快速全景）、深度优先（挖细节）、稀疏注意力（聚焦关键节点）、混合式（多策略并行）。

**阶段3 原子搜索**：每个子问题至少 3 种关键词组合、每种组合至少 2 类信源；用 WebSearch/WebFetch 并行执行，每次搜索聚焦一个原子问题。**搜索铺面（WebSearch）、取证核原文（WebFetch）分工执行；20-30% 轮次用于反方检索；边搜边记证据台账。**（细则见 search-playbook.md 第二、四、五节）

**阶段4 信源分级**：
- S级（0.9-1.0）：官方文档、工商年报、法院判决书、顶会顶刊（NeurIPS/ICML/Nature/Science）、一手数据
- A级（0.7-0.89）：工商数据平台（天眼查/企查查/爱企查）、权威报告（Gartner/McKinsey）、知名媒体深度报道、行业白皮书
- B级（0.5-0.69）：企业自述渠道（官网/招聘页/展会稿）、一般论文、技术博客、社区讨论
- C级（0.3-0.49）：预印本（arXiv）、一般新闻、社交媒体、匿名来源

处理规则：S/A 级可直接引用；B 级显名归因；C 级需交叉验证，仅作线索。

**阶段5 交叉验证**：核心事实至少 3 个独立来源确认；关键数据追溯到原始出处；矛盾信息必须标记并分析；呈现不同立场观点（支持方/反对方/中立方 + 各自证据）。

**阶段6 迭代反思**：检查是否覆盖所有子问题、有无新问题、信息是否足够支撑结论、逻辑链条是否完整；信息饱和度>90% 或无新发现时终止（默认最多 3 轮）。

**阶段7 结论输出**：最高确定性结论（标注置信度：高>90%/中70-90%/低<70%）、最值得跟踪的变化变量、最容易误判的点、风险因素与反证条件。

**阶段8 报告生成**：Markdown 为主（规格见 report-standards.md）；用户要求时生成交互式 HTML（规格见 SKILL.md 阶段 8 路线 B）。

## 二、稀疏混合式注意力搜索（搜索内功）

核心思想：不是对所有信息均匀关注，而是识别并聚焦高价值信息节点（全量信息 → 价值评估 → 稀疏选择 → 深度聚焦）。处理 10 倍信息量，耗时仅增 2 倍。

四阶段：
1. **广度扫描**（低精度高覆盖）：核心词+同义词+上位词，均匀注意力；产出领域全景图、关键主题列表、初步问题清单
2. **焦点识别**（中精度中覆盖）：基于扫描结果精准搜索，按相关性加权；产出高价值信息源清单、研究空白
3. **深度挖掘**（高精度低覆盖）：精确匹配、引用追踪、作者追踪、项目追踪；高度集中于 S/A 级信源
4. **交叉验证**：验证矩阵（3 源 ✓✓✓=高置信，✓✓✗=中，✓✗✗=低需再验证）

**Scale 策略**（宏观→微观四层）：全景扫描（广度）→ 热点追踪（强度）→ 深度挖掘（深度）→ 细节验证（精度）。

**注意力分数** = 信源权威性×0.30 + 内容相关性×0.25 + 时间新鲜度×0.20 + 数据完整性×0.15 + 交叉验证×0.10

**节点筛选权重**：时效性 30% + 权威性 25% + 相关性 25% + 独特性 20%；评分>80 立即深挖，60-80 标记待后续，<60 跳过。

**时间新鲜度**：≤7天=1.0，≤30天=0.9，≤90天=0.8，≤1年=0.6，≤2年=0.4，更早=0.2。

## 三、深度挖掘技法

1. **引用追踪**：从一篇核心文献出发——前向（谁引用了它，发现后续研究）、后向（它引用了谁，找理论根基）、相关推荐（补遗漏）。
2. **作者追踪**：识别领域专家，追踪其最新发表与引用网络。
3. **项目追踪**：关注核心开源项目 Star/Fork 趋势、Issue/PR 与版本发布。
4. **高级搜索语法**：精确匹配 `"..."`、排除词 `词 -排除`、作者 `author:"名"`、来源/站内 `site:`、标题 `intitle:`、文件类型 `filetype:pdf`、时间范围限定。

## 四、多任务并行搜索与轮回管理

- **维度并行**：技术 + 商业 + 政策 + 用户
- **信源并行**：学术（Google Scholar/arXiv/Semantic Scholar）+ 新闻 + 社区（知乎/V2EX/Reddit/HN）+ 官方（官网/GitHub/文档）
- **语言并行**：中文 + 英文
- 工具层面：单条消息内并行发起多个 WebSearch/WebFetch 调用

**搜索轮回分配**（深度档 20-30 轮）：全景扫描 5-8 / 节点筛选 3-5 / 深度挖掘 8-12 / 交叉验证 3-5 / 迭代补充 2-3。

## 五、交叉验证技法

1. **事实核对**：同一事实至少 3 个独立来源确认，例：论文A 95% / 论文B 94.8% / 官方文档 95.2% → 高置信"约95%"。
2. **数据验证**：关键数据追溯原始出处；官方未确认的流传数据标低置信（如"GPT-4 参数量 1.8 万亿"仅见于非官方博客 → 低置信）。
3. **观点对比**：支持方/反对方/中立方 + 各自证据，综合评估。

**冲突处理**：记录不同来源的差异 → 分析差异原因 → 给出综合判断和置信度 → 写入矛盾清单（禁止抹平）。

## 六、学术调研速查（详版）

### 6.1 平台分工与各自的脾气

| 平台 | 强项 | 坑 |
|---|---|---|
| Google Scholar | 覆盖最广、被引追踪 | 无法精确限定字段，结果混入非论文；用 `site:` / `intitle:` 收窄 |
| Semantic Scholar | 引用图谱、TLDR 摘要 | 收录偏新，老年份文献可能缺 |
| arXiv | 预印本最快、全文免费 | **未经同行评审**，只能作 C 级线索；比正式发表早 6-18 个月 |
| PubMed | 生物医学权威 | 只覆盖医学；需用 MeSH 主题词才准 |
| IEEE Xplore · ACM DL | 工程 / CS 顶会顶刊 | 大量需订阅，通常只能读到摘要 |
| 百度学术 · CNKI | 中文文献主力 | CNKI 需机构权限；百度学术索引不全 |
| Nature · Science | 顶刊标杆 | 摘要可读，正文需订阅 |

### 6.2 检索式怎么造（四要素）

1. **布尔逻辑**：`AND` 收窄交集 / `OR` 扩召回（同义词并联）/ `NOT` 排干扰
2. **字段限定**：`intitle:` 标题 · `author:"姓名"` 作者 · `source:` 期刊 · `site:` 站内
3. **精确匹配**：`"完整短语"` 用引号锁死，防分词漂移
4. **截词通配**：`comput*` 命中 computer / computing / computation（部分库不支持）

**模板**：

```
("核心术语" OR "同义词" OR "英文缩写")
  AND ("第二术语" OR "其同义词")
  AND (site:arxiv.org OR site:dl.acm.org)
```

> 换库就要改写检索式——各库对布尔与字段的语法支持并不统一。

### 6.3 时间与排序策略

- **时间四档**：最新研究（近 1 年）/ 近期热点（近 2-3 年）/ 经典文献（高被引，不限年份）/ 历史溯源（追到源头）
- **排序三选**：相关性（找方向）→ 引用数（找奠基作）→ 时间（找最新进展）；三者交替用，别只按一个排

### 6.4 三遍阅读法（成本递增，随时可弃）

| 遍次 | 耗时 | 看什么 | 产出 |
|---|---|---|---|
| 快读 | 5-10 分钟 | 标题 / 摘要 / 结论 / 图表 | 决定这篇要不要留 |
| 细读 | 1-2 小时 | 引言 / 方法 / 结果 | 抓结论与证据强度 |
| 精读 | 3-5 小时 | 复现思路、批判、改进空间 | 判断可信度与可迁移性 |

### 6.5 系统性文献综述流程（照着走）

定义问题 → 制定检索策略（多库 + 多词组合）→ 筛选（标题→摘要→全文，收 100+ 留 50）→ 质量评估 → 数据提取（统一表格）→ 主题归纳（趋势 / 分歧 / 空白）→ 撰写

**「质量评估」三道尺**：① 样本量与代表性；② 方法是否可复现；③ 结论与数据是否匹配。

### 6.6 引用质量怎么判

- 看**总量**、**顶会顶刊引用占比**、**引用语境**（正面 / 负面 / 中性）、**自引比例**、**增长趋势**
- **h-index 跨领域不可比**（数学 20 ≠ 生物 20）
- 高被引 ≠ 高质量：综述天然引用高，要区分"被引用"与"被认可"

## 七、新闻与舆情速查（详版）

### 7.1 信源矩阵与可信度分层

| 类别 | 代表 | 用法 |
|---|---|---|
| 官方一手 | 政府公告、企业公告、法院文书 | S 级，可直接引用 |
| 财经媒体 | 财联社 / 华尔街见闻 / 证券时报 / 36氪 | A 级，先判是否转载通稿 |
| 科技社区 | Hacker News / V2EX / 少数派 / Product Hunt | B 级，看风向与从业者观点 |
| 社交平台 | 微博 / 知乎 / 小红书 | C 级，仅作线索与情绪样本 |
| 国际媒体 | Reuters / BBC / Guardian / Bloomberg | A 级，跨境事件优先看 |

**一眼识破通稿**：多家媒体同一时段、同一措辞、无独立采访、不署记者名 → 本质是单一信源，**不能算「多来源验证」**。

### 7.2 时间过滤四档

实时热点 24h / 近期动态 1 周 / 趋势分析 1 月 / 深度回顾 1 年 / 历史背景不限

> 舆情检索的**第一动作是锁定时间窗**——同一话题在 24 小时内和 3 个月后的结论，经常是反的。

### 7.3 关键词要搜"人话"

- 正式词之外，补 **网络用语 + 谐音 + 缩写 + 黑话**（例：查"裁员"要同时搜"优化""毕业""人员调整"）
- 品牌要搜**别名 / 曾用名 / 英文名 / 产品名**（改名会导致历史信息断层）
- 争议事件加**立场词**（"避雷""踩坑""真香""翻车"）激活真实用户表达

### 7.4 事件追踪框架（还原时间线）

1. **事件概述**：名称 / 时间 / 影响范围 / 关键人物
2. **发展时间线**：起因 → 转折 → 各方反应 → 最新进展
3. **多方观点**：官方 / 媒体 / 专家 / 公众，四方立场分别归位
4. **影响分析**：短期 / 长期 / 风险 / 应对建议

### 7.5 舆情指标（量化了才叫分析）

- **热度指数**：讨论量 / 阅读量 / 转发量加权
- **情感倾向**：正 / 中 / 负比例——**必须标注采样范围与样本量**，否则等于拍脑袋
- **传播路径**：首发平台 → 扩散节点 → 二次发酵点
- **关键意见领袖**：谁在带节奏，是利益相关方还是旁观者

### 7.6 三个必踩的坑

1. **水军刷量**：短时间同质评论、账号新注册、无历史内容 → 剔除后再算情感比例
2. **情绪 ≠ 事实**：舆情只反映"大家怎么说"，不等于"事情是什么"；事实链路仍需 S/A 级信源
3. **截图无源**：社媒截图不可作为证据，必须回溯到原始发布链接与发布者身份

## 八、执行标准（硬指标）

- 搜索深度：基础 10-15 轮 / 标准 15-20 轮 / 深度 20-30 轮
- 信源覆盖：≥3 种类型信源、≥2 种语言、S/A 级占比 ≥40%
- 交叉验证：核心事实 ≥3 独立来源；矛盾必须标注
- 结论必须带置信度；区分事实 / 推论 / 判断三个层级

**质量检查清单**：覆盖所有子问题？有 S/A 级信源支撑？核心事实经交叉验证？包含最新进展？有多元视角和反方意见？

## 九、常见错误清单（自检）

- 关键词太窄漏信息 / 只用单一信源 / 只搜中文
- 只收集不分析、忽视矛盾信息、不区分事实与观点
- 不注明来源、不标置信度、不解释推理逻辑
- 过度依赖单一来源、只看摘要不看全文、不核实原始出处
